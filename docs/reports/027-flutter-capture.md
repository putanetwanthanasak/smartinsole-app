**Inclusion criteria** (user, 2026-10-22, from doc 03), in
`mobile/lib/capture/capture_protocol.dart`:
- the age-range choices are **21–25 / 26–30**, since doc 03 only admits
  volunteers aged 21–30 (`ageRanges`);
- for `SI-` codes, a foot length outside **25.5–27.5 cm** (inclusive) is
  shown in the form with "Does not meet the inclusion criteria (foot
  length 25.5–27.5 cm)." and Start stays disabled
  (`footLengthEligible`). `CaptureSession.create` also refuses such a
  subject, so a study session's files never hold one. `TEST-` codes take
  any value.

**Required fields** (user, 2026-10-23): for an `SI-` code, sex, age
range, both foot lengths and the room temperature (doc 03 records it
every time) are all required. `missingForStudy()` in
`capture_session.dart` is the one rule:
- the form shows "Required for SI- codes: …" and keeps Start disabled;
- a filled field that isn't a number shows "Not a number";
- `CaptureSession.create` refuses an incomplete study subject.

`TEST-` codes keep every field optional. Both guards were checked by
removing them, and each removal fails "SI codes need every field".

### Files

Everything is under `<app documents>/research/<code>_<yyyymmdd-HHmmss>/`
(private storage):
- **`<code>_<nn>_<label>_a<k>.csv`**, one per attempt. Long format, one
  row per sample per foot:
  - timing: `unix_ms` (DeviceClock, 3 decimals), `device_ms`;
  - stream: `side`, `conn_session`, `seq`, `i`, `missing_before`;
  - flags: `saturated`, `calibrating`, `valid`;
  - values: `fsr0..5_adc`, `fsr0..5_kpa`, `accel_*_g`, `gyro_*_dps`;
  - temperature: `temp_unix_ms`, `temp_forefoot_c`, `temp_heel_c`,
    `temp_quality`, set on the first row after each reading.

  The per-foot column names are the `model_input.json` names without
  `L_` / `R_` (a test checks this). Values come from the app's parser,
  which is checked against `shared/test_vectors/`. The loader never
  converts again, so there is one conversion code path, as SESSIONS
  requires.
- **`…_a<k>.json` sidecar**:
  - the gait and its model index, the pain side / rotation;
  - planned vs actual duration, the window `[start, end)`;
  - the end reason (`completed` / `stopped_early` / `interrupted`), and
    `valid` with its invalid reason (`redo`, `interrupted`);
  - marked segments and gaps;
  - per foot: device id, full calibration table, firmware, battery at
    start and end, packet and sample counts, sessions, temperature
    readings;
  - the app version and the timings used.
- **`session.json`**:
  - the code and coded subject data only;
  - the trial order and seed, and the pain side;
  - the calibration summary: resting kPa per channel, starting
    temperatures, starting ΔT;
  - every attempt, and every export.
- **`manifest.json`**, written at export: the size and SHA-256 of every
  file.

### Design decisions

- **Windowed recording, deadlines not ticks.** Each recording has a
  window `[start, start + planned)` on the unix clock. The 250 ms tick
  only compares `now` with the deadline. The recorder writes only samples
  whose `unix_ms` is inside the window. After the deadline, a 600 ms grace
  period lets packets already in flight land; then the files are closed.
  A starved timer (pocket, screen dim) can delay a cue, but it can't
  stretch or shorten the data. Mutation M1 checks this.
- **Gaps are written down, never smoothed over:**
  - `seq_gap` (missing packets);
  - `missing_at_start`;
  - `link_lost` (from-to unix, with the session change);
  - `no_data_at_start` / `no_data_at_end` / `no_data` (more than 500 ms
    from a window edge).

  A link loss cues every 5 s until the foot is back, and recording
  continues after the reconnect (SESSIONS item 3).
- **File and sidecar always agree.** A marked segment's edges, and an
  early stop's cut, are clamped to just after the last row written. This
  was found because the fixture had one row more than the window said
  (312 vs 311). Mutation M4 checks it.
- **Nothing is overwritten:**
  - A redo marks the old sidecar `valid: false, invalidReason: redo` and
    records `a2`.
  - A crash leaves the open attempt `interrupted`; it is finalised on
    Resume.
  - Leaving the screen mid-recording does the same.
  - Files go only through "Delete from phone", which is available after an
    export and confirmed twice.
- **Pocket safety:**
  - While recording, nothing reacts to a short touch, and Back is
    blocked.
  - The two controls are 2 s holds, which cancel if the finger slides.
  - The screen stays on for the whole flow.
- **Export route:** files are staged in the app-specific external folder,
  then `adb pull` with SHA-256 checks. This works on a release build,
  where `run-as` doesn't. Other apps can't read the folder on Android 11+.
- **Rehearsal timers** are used for `TEST-` codes only: 10 s calibration,
  30 s trials, 5 s practice. `SI-` codes always use the study timers
  (30 s / 3 min / 30 s).

   runs with stdin closed, and a closed stdin means "no".
